🗳️ Projet Élections — Plateforme électorale temps réel multi-cloud

Diae EL Mokhtari · Aya Khadraoui · Hind EL YOUBI · Ibtissam EL ASSLOUJ — Cloud Computing

En une phrase : les bureaux de vote publient leurs résultats en direct, les fraudes sont détectées automatiquement, et si le cloud primaire tombe en panne, le cloud de secours synchronisé prend le relais sans aucune intervention — 6 clouds, 5 fournisseurs différents.

1 · Le trajet d'un vote

Bureau de vote → Portail de soumission → API d'ingestion → « Quel cloud est actif ? » → Failover Controller → Kafka → Agrégateur + Moteur d'anomalies → PostgreSQL → Dashboard public
Fraudes détectées → Worker Cloudflare → Telegram (notification instantanée aux admins)

3 · Le mécanisme star : le failover

  • Prometheus sonde en permanence les métriques d'Azure et d'Oracle.
  • Si Azure tombe en panne → alerte AzureDown → le Failover Controller répond « oracle » quand on lui demande le cloud actif.
  • L'API d'ingestion route alors tous les nouveaux votes vers Oracle, déjà synchronisé : aucune voix perdue. Quand Azure revient, tout se resynchronise (MirrorMaker 2 et Patroni le gèrent).
